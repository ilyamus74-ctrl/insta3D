# Patch bundle: generated merge deletion + optional AprilTag assist

Base commit: `896f08c9a7b15fdb849827dca8737f0fcdf8f927` (`main`, 2026-07-26).

## Included patches

1. `20260726_generated_merge_delete_queue.patch`
   - keeps web deletion atomic: the PHP request renames the assembly into `.delete_merge_<id>_<token>`;
   - removes recursive deletion from the `apache` request;
   - adds a root-side systemd timer that safely removes quarantined root-owned trees;
   - adds a cleanup test.

2. `20260726_apriltag_assist_helper.patch`
   - adds the optional AprilTag analysis helper;
   - scans only frames registered in COLMAP sparse components;
   - uses an existing C++ detector first, then OpenCV ArUco as fallback;
   - requires at least three registered observations of the same tag per component.

3. `20260726_apriltag_assist_integration.patch`
   - integrates the helper into the existing COLMAP sparse and dense path;
   - reports `MARKERS_NOT_FOUND`, `MARKERS_INSUFFICIENT`, `MARKERS_DISCONNECTED`, `MARKERS_READY`, or detector/helper errors;
   - never fails the primary reconstruction merely because tags are absent;
   - propagates the warning into sparse and dense `status.json` and `result.json`;
   - keeps `assist_only=true` and `sim3_applied=false`: actual Sim3 application is not falsely reported.

## Deploy deletion cleanup

```bash
sudo cp web/remote_station/makler-generated-merge-cleanup.service \
  /etc/systemd/system/
sudo cp web/remote_station/makler-generated-merge-cleanup.timer \
  /etc/systemd/system/

sudo systemctl daemon-reload
sudo systemctl enable --now makler-generated-merge-cleanup.timer
sudo systemctl start makler-generated-merge-cleanup.service

systemctl status makler-generated-merge-cleanup.timer --no-pager
journalctl -u makler-generated-merge-cleanup.service -n 100 --no-pager
```

Safe preflight:

```bash
sudo php \
  /home/makler/web/remote_station/cleanup_generated_merge_quarantine.php \
  --dry-run
```

The real service runs as `root`. The web request only performs the atomic rename and never receives recursive-delete privileges.

## Deploy AprilTag assist to the station

The helper is a `.sh` file, so the existing station installer uploads it with the other processing scripts:

```bash
cd /home/makler/web
./remote_station/install_station.sh ./remote_station/stations.conf
```

Optional environment variables:

```bash
APRILTAG_ASSIST_ENABLED=1
APRILTAG_TAG_FAMILY=tag36h11
APRILTAG_MARKER_SIZE_M=0.160
APRILTAG_VALID_IDS=1-30
APRILTAG_MIN_OBSERVATIONS=3
APRILTAG_MAX_OBSERVATIONS_PER_TAG=20
APRILTAG_DETECTOR_BIN=/path/to/detect_markers
```

Detection order:

1. explicit/existing `detect_markers` C++ binary;
2. OpenCV `aruco.DICT_APRILTAG_36h11`;
3. non-fatal `MARKER_DETECTOR_UNAVAILABLE` warning.

## Runtime behavior

Without tags, the job remains `DONE`. The displayed job message contains:

> AprilTag-метки не обнаружены. Модель построена без маркерной привязки. Масштаб может быть неметрическим, а при нескольких SfM-компонентах возможны проблемы их стыковки.

With sufficient observations, `apriltag_assist.json` records which components are scale-ready and whether a shared tag can act as a future component bridge. Actual Sim3 estimation/application is deliberately left for the next patch.
